# my-daep

**Distributed Agent Execution Platform** — явно включаемый распределённый режим разработки в OpenCode.

Пользователь работает в существующем GitHub-проекте на DevCoveer и указывает: выполнить задачу распределённо на Kaggle. Основная модель делит работу, отдельные OpenCode в 1–4 notebooks реализуют независимые части. DAEP сохраняет изменения в GitHub, восстанавливает сбои, возвращает результаты координатору для интеграции и сквозных проверок либо передачи в ChatGPT.

## Начать реализацию

- **[Итоговый проект v1](docs/distributed-mode.md)** — единственный актуальный контракт: GitHub, App/credentials, распределённая работа, наблюдение, восстановление и приёмка.
- **[Постановка для нового окна ChatGPT](docs/implementation-task.md)** — конкретная задача source-реализации, установки и проверяемого coding-пилота.

## Целевая схема

```text
OpenCode на DevCoveer: задача, план, интеграция, сквозные проверки
                     ↕
DAEP: supervisor + SQLite + GitHub App broker + глобальный tool/CLI
                     ↕
         1–4 Kaggle notebooks: wrapper + OpenCode
                     ↕
GitHub целевого проекта: base SHA → attempt-ветки → integration-ветка → один PR
                     ↓
       существующие CI / инфраструктура / исправления в ChatGPT
```

Модель управляет содержанием работы. Supervisor-код управляет ресурсами, повторными попытками и сохранностью независимо от LLM и открытого окна. Обратная доставка событий координатору и его восстановление входят в реализацию, а не оставляются ручным polling.

## GitHub и доступ

GitHub — обязательный источник кода и место сохранения code checkpoints/результатов. Для пилота допустима существующая GitHub App dataset-loop с отдельным PEM-ключом; отдельная App использует тот же конфигурационный интерфейс. Фактический доступ к выбранным репозиториям проверяется до notebook launch.

PEM остаётся на DevCoveer. Notebook получает короткий installation token через broker и обновляет его автоматически до истечения. GitHub App token не является ограничением одной веткой; DAEP отдельно проверяет попытку и принятый commit. Итоговый PR один на job, не по PR на каждый notebook.

GitHub не хранит живую очередь, heartbeats, SQLite, build cache и полные session dumps. Они остаются в runtime state и ограниченном внешнем storage/backup. Никакого нового GitHub runner, webhook или запуска `/opencode` через комментарии для DAEP v1.

## Границы

Только Kaggle; ручной/auto предел 1–4 и общий максимум четыре; разные проекты через один глобальный вход. Нельзя молча заменить distributed mode локальным кодингом. Другие backend, MCP/OAuth, dataset-loop migration, собственный CI/CD/UI, модельный gateway и автоматическая починка самого DAEP — позже.

Классификация исходников и система запретов передачи кода моделям исключены. Модели Zen/NVIDIA/GPT и другие выбираются через OpenCode по настройкам задачи; фактический выбор, переключения, расходы/unknown и ошибки видны.

Первая продуктовая приёмка: две реальные перекрывающиеся coding-подзадачи в Kaggle, события до окончания, Git checkpoints, восстановление одной части после сбоя без потери другой, интеграция и проверки итогового SHA. Unit/fake-provider тесты нужны, но не заменяют этот live-путь.

Этот репозиторий — код инструмента и необходимая документация, не датасет. `data/sample_data.csv` — оставшийся исходный шаблон, не часть DAEP runtime.
