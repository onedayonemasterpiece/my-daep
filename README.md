# my-daep

**Distributed Agent Execution Platform** — явно включаемый распределённый режим работы OpenCode над кодом.

Пользователь ставит задачу в текущем проекте на DevCoveer и указывает распределённое исполнение на Kaggle. Основная модель делит работу на независимые части; отдельные OpenCode выполняют их в 1–4 notebooks. Основной OpenCode наблюдает ход, объединяет результат и проводит сквозные проверки либо готовит пакет для исправлений в ChatGPT.

## Текущее состояние

**Зафиксирована постановка. Исполняемый DAEP, установка, интеграция OpenCode и live Kaggle-прогон ещё не реализованы в этом репозитории.** Документация не означает готовность runtime.

Один актуальный документ реализации: **[docs/distributed-mode.md](docs/distributed-mode.md)**. Он содержит поведение, восстановление, точки повторного использования и конкретную первую source-задачу с приёмкой.

## Как должна работать первая версия

```text
Задача + явное указание «распределённо на Kaggle»
                         ↓
OpenCode-координатор: план и независимые части
                         ↓
DAEP supervisor: учёт ресурсов, запуск, наблюдение, восстановление
                         ↓
            1–4 Kaggle notebooks с OpenCode
                         ↓
         сохранённые изменения и реальные проверки
                         ↓
OpenCode: интеграция + сквозные тесты / пакет для ChatGPT
```

Модель управляет содержанием работы. Обычный supervisor-код управляет жизненным циклом notebooks и продолжает сопровождение независимо от доступности модели и открытого окна.

Количество notebooks задаётся вручную либо автоматически в пределах четырёх с учётом независимых подзадач и фактической ёмкости Kaggle. Запрошенное и реально исполняющееся количество показываются раздельно. Недоступность ресурса не приводит к скрытому переключению coding-задачи на локальное исполнение.

Notebook отправляет события и checkpoints через исходящий HTTPS-канал к supervisor; в ответ получает команды. Отдельный публичный HTTP-сервер в каждом notebook не требуется. Для первого разворота нужен один доступный из Kaggle endpoint supervisor.

## Scope

В первой версии: Kaggle, несколько проектов через один глобальный вход OpenCode, ручной/auto parallelism 1–4, наблюдение по ходу, сохранение и автоматическое восстановление, интеграция, проверки и пригодный для продолжения в ChatGPT результат.

**Классификация кода и система запретов передачи кода моделям исключены.** Zen, NVIDIA и дополнительные GPT/другие модели подключаются через возможности OpenCode; фактическая модель и причины переключений видны пользователю.

MCP, другие runtime-адаптеры и миграция dataset-loop — последующие возможности, не обязательные зависимости пилота. Не строить собственный CI/CD, UI, кластер, model gateway или многоступенчатый комитет агентов.

## Хранение

Этот репозиторий — код DAEP и необходимая документация, не датасет. `data/sample_data.csv` остался от первоначального шаблона и не является частью runtime. Логи, checkpoints, backups и журналы jobs не должны накапливаться ни здесь, ни в продуктовых репозиториях.

Первая продуктовая проверка: две реальные параллельные coding-подзадачи в Kaggle, восстановление одной после сбоя, сохранение обоих результатов и успешная проверка их интеграции. До такого прогона рабочая распределённая схема не заявляется.
